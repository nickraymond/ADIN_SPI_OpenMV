📖 Label review — correct the training boxes by hand

S8 bite B3. The GUI runs on the Mac (that is where the datasets live — never in the repo, never on the Pi). This page is the recipe card's "chapter": follow it top to bottom.

Labeler status: checking… Open the labeler →

1. Start the GUI on the Mac

For the urchin sets (bite E — GBIF auto-box review etc.), point it at the datasets root and pick the set (e.g. gbif_inat) from the dropdown:

python3 ~/Documents/GitHub/ADIN_SPI_OpenMV/ml/fomo/label_gui.py ~/nereus_ml/datasets

For the original two-ball captures, the no-argument form still works (its default root is ~/nereus_ml/datasets/two_ball):

python3 ~/Documents/GitHub/ADIN_SPI_OpenMV/ml/fomo/label_gui.py

Absolute path — runs from any directory, any python3 (the GUI is stdlib-only). LAN bind, port 8899.

If the venv does not exist yet (fresh Mac), rebuild it first:

/opt/homebrew/bin/python3.11 -m venv ~/nereus_ml/venvs/fomo
~/nereus_ml/venvs/fomo/bin/pip install tensorflow

(TensorFlow is only needed for retraining, not for the GUI itself — the GUI is stdlib-only. Any python3 runs it.)

1b. Stop / reload it

Ctrl-C in the terminal that runs it is the whole stop story — every frame is saved the moment you move off it, so nothing is pending. The GUI reads its labels.jsonl files once at startup, so after anything regenerates labels (an auto-box pass, a relabel run, a new set added), reload = stop it and start it again.

If the start fails with OSError: [Errno 48] Address already in use, an older instance is still holding port 8899 — typically a GUI whose terminal window was closed or disconnected (closing the terminal does NOT reliably kill it). Find and stop it, then start fresh:

lsof -ti :8899 | xargs kill

(Safe: kill's default signal lets it exit cleanly, and the GUI never has unsaved state. Seen live 2026-08-22: a labeler from a 19-hour-old session held the port after its terminal vanished.)

2. Open it

The badge above turns green when the labeler answers; the link appears next to it. The name is the Mac's Bonjour hostname (scutil --get LocalHostName → Nicks-MacBook-Pro, verified 2026-08-21 — NOT the shell's hostname). If .local does not resolve on your network, use the Mac's IP or tailnet name instead — the URL lives in ONE place in this file (the "Open the labeler" link's href; the status probe derives from it), in pi/workbench/recipes/guides/label-review.html.

3. Review frames

  • ←/→ moves between frames — moving off a frame saves it and marks it reviewed (the ✓ and the reviewed count in the top bar)
  • space jumps to the next unreviewed frame
  • drag on empty image = draw a box (current class) · drag inside a box = move · drag its corner = resize · click = select
  • 1–9 set the class (of the selected box, else the drawing class) · x delete · c clear ALL boxes on the frame (= exclude the whole image; arrow off to save it reviewed-empty) · u undo
  • The green bar in the top strip is your progress: reviewed frames / total in the current set.
  • + class adds a new class (urchins ride this same tool — the class list is never hard-wired). Classes can only be ADDED, never removed: removal would renumber every existing box.

Edits go straight back into the same labels.jsonl the trainer reads. There is no export step.

4. Retrain on the corrections

~/nereus_ml/venvs/fomo/bin/python ~/Documents/GitHub/ADIN_SPI_OpenMV/ml/fomo/train.py

Known B2 debts your corrections attack: the USPS-box lettering learned as purple, dim-pink recall on the AE3, exact-count weakness. Compare the printed val precision/recall against B2's 0.73/0.87.

Do not re-run ml/fomo/relabel.py after correcting — it regenerates auto-labels. It now refuses to overwrite a file containing reviewed frames unless given --force, which discards your corrections.

5. Ship the retrained model

Compile + deploy by the proven B1 routes (ml/README.md): AE3 = vela → /flash; N6 = ROMFS image → USB DFU alt 3 (never alt 0). Update the s8-two-colour-model recipe's sha256s so reconciliation owns the new bytes.
