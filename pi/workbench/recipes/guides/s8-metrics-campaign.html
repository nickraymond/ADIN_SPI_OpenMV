📊 S8 accuracy campaign — collect rows, render the report

S8 bite C. Run the whole thing from a terminal ON THE PI (ssh pi@nereus000, then cd ~/ADIN_SPI_OpenMV). Total bench time ~20–30 min. Rows accumulate in ~/s8_rows.jsonl (outside the repo); the report renders into the workbench as its own chapter.

0. Free the boards

On the workbench page: stop anything LIVE, wait out the settle countdown. The collector below owns both ports itself.

1. One recording run per ball arrangement (do 4)

Arrange the balls, count them — the truth counts you type here are the ground truth for everything downstream — then run (edit --truth and --run-label each time):

python3 bench/n6_stream_host.py \
  --bind 0.0.0.0 --framesize VGA --max-seconds 60 \
  --record ~/s8_rows.jsonl --run-label arr1 --truth "pink=11,purple=10" \
  --board AE3=/dev/serial/by-id/usb-OpenMV_OpenMV_Camera_0829c14000000000-if00 \
  --board N6=/dev/serial/by-id/usb-MicroPython_Pyboard_Virtual_Comm_Port_in_FS_Mode_020023000450433547373200-if00 \
  --board-model AE3:/flash/nereus_two_ball.tflite \
  --board-model N6:/rom/nereus_two_ball.tflite \
  --board-thresh AE3:pink:28,75,14,32,-12,6 \
  --board-thresh AE3:purple:15,65,3,18,-40,-13 \
  --board-thresh N6:pink:28,80,23,50,-19,-2 \
  --board-thresh N6:purple:20,65,8,38,-70,-20 \
  --board-pixels AE3:60 --board-pixels N6:150

It ends by itself after 60 s and prints recorded N rows to ~/s8_rows.jsonl (run=arr1) — that line is the artifact check, look for it. Watch live at :8090 while it runs. Truth order must be pink,purple (the recipe's threshold order). Vary the counts between arrangements — e.g. 11/10, 5/5, 2/8, 0/6 — an accuracy number needs truth variation. Wait ~35 s between runs (the same AE3 settle rule the workbench enforces).

2. Power readings (one USB meter, swapped between runs)

During any run: read watts for the board on the meter, then swap the meter to the other board's cable for the next run and read again. Same model + same scene class → constant-load assumption holds at this granularity (your call, 2026-08-21). Note both numbers — they go on the report command line in step 4.

3. Inference-only ceilings (~2 min, one command per board)

With the workbench idle and ≥35 s since the last run ended (one attempt, no retry loops — if the AE3 refuses, leave it and ship the report without this column):

mpremote connect /dev/serial/by-id/usb-MicroPython_Pyboard_Virtual_Comm_Port_in_FS_Mode_020023000450433547373200-if00 run bench/s8_infer_probe.py
mpremote connect /dev/serial/by-id/usb-OpenMV_OpenMV_Camera_0829c14000000000-if00 run bench/s8_infer_probe.py

Each prints one #P {...} line with infer_per_s (N6 first, then AE3 — the AE3 is the settle-fussy one, touch it last).

4. Render the report

python3 bench/s8_report.py ~/s8_rows.jsonl \
  --power "AE3=0.21,N6=1.02" \
  --infer-only "AE3=27.5,N6=42.0"

Substitute your measured numbers; drop either flag if you skipped that measurement — the column prints "not measured" rather than a guess. The command prints the row count it consumed — check it matches what you recorded.

5. Read it

Refresh the workbench page → open the “S8 accuracy report” card (it replaces the placeholder page the repo ships). The Pi's git tree will show the report file as modified — commit it to bank the campaign, or git checkout -- pi/workbench/recipes/guides/s8-metrics-report.html to discard.

If a run dies mid-way (board unplug, Ctrl-C), the partial rows are already in the file — re-run the SAME arrangement with a fresh --run-label (e.g. arr2b) and ignore the dead label when reading the report: partial runs show as low-frame cells, they do not poison other runs.
